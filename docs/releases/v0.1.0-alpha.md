# HyperAgent v0.1.0-alpha Release Notes

HyperAgent `v0.1.0-alpha` is the first early open-source developer preview of the Codex-first HyperAgent loop.

Release posture: local, markdown-first, inspectable, and human-review-required.

## What HyperAgent Is

HyperAgent is an open source "Iron Man Suit" for AI agents. It gives Codex a local operating layer for doing work, recording evidence, proposing upgrades, and reviewing the improvement process.

The core loop is:

```text
Mission -> Workshop -> Forge -> Human Review
```

## What Works

- Codex-compatible `codex-hyperagent` skill.
- Local installer for Codex skills.
- Mission records in `missions/`.
- Workshop proposals in `workshop/proposals/`.
- Human approval or rejection records in `workshop/decisions/`.
- Accepted capability registry in `hyperagent/capability-registry.md`.
- Forge reviews in `forge/reviews/`.
- Local verification with `scripts/verify-mvp.sh`.
- End-to-end smoke loop with `evals/smoke-loop.sh`.

## Install

```bash
git clone https://github.com/DannyMac180/HyperAgent.git
cd HyperAgent
sh scripts/install-codex-skill.sh "$HOME/.codex/skills"
```

For active development:

```bash
sh scripts/install-codex-skill.sh --symlink "$HOME/.codex/skills"
```

Restart Codex Desktop or open a fresh thread after installing or updating the skill.

## Update

For copy installs:

```bash
git pull
sh scripts/install-codex-skill.sh --force "$HOME/.codex/skills"
sh scripts/verify-mvp.sh
```

For symlink installs:

```bash
git pull
sh scripts/verify-mvp.sh
```

Symlink installs update automatically because the installed skill points back to the clone.

## First Run

Ask Codex:

```text
Use $codex-hyperagent to run this as a HyperAgent mission, verify the result, write a mission record, and propose upgrades only if there is concrete friction.
```

See `docs/quickstart.md` for the full walkthrough.

## Verification

```bash
sh scripts/verify-mvp.sh
sh evals/smoke-loop.sh
sh scripts/hyperagent.sh status
```

## Forge Review Flow

The Forge improves the Workshop. It does not modify the user's code directly.

For alpha, Forge reviews:

- review recent Workshop proposals,
- judge whether proposals are specific, evidence-backed, testable, safe, and worth installing,
- judge whether accepted upgrades improved behavior and paid off,
- identify weak evals, vague upgrade ideas, and process bloat,
- write reviews in `forge/reviews/`,
- propose process improvements without silently activating them.

Run a Forge review after proposal decisions, eval changes, release-readiness checks, or repeated missions that produce vague Workshop output.

Run:

```bash
sh scripts/hyperagent.sh forge-prompt
```

Then have Codex follow the prompt.

When a Forge review finds process friction, create the follow-up proposal from that review:

```bash
sh scripts/hyperagent.sh propose-upgrade \
  --forge-review forge/reviews/2026-05-16-1216-workshop-quality-review.md \
  --title "Improve Workshop proposal quality" \
  --problem "Recent proposals are too vague to evaluate safely"
```

## Current Limitations

HyperAgent alpha does not provide:

- autonomous self-modification,
- hosted memory,
- a polished UI,
- multi-platform support beyond Codex,
- automatic upgrades across every user project,
- production-grade safety automation.

## Safety And Human Review

Persistent behavior changes require human review.

HyperAgent agents may propose upgrades and draft local low-risk files. They may not silently broaden filesystem, shell, network, deployment, account, or secrets access. They may not silently alter secrets handling.
