## Problem

- Problem observed: A Python verifier failed before checking demo behavior because `py_compile` attempted to write bytecode into a macOS user cache path outside the workspace sandbox.
- Evidence from mission records: `missions/2026-05-20-1959-agents-sdk-demo.md` records the failed verifier run and the local fix.
- Why the current Suit was insufficient: HyperAgent has shell verifier patterns, but no reusable guidance for Python checks that need deterministic bytecode-cache behavior under sandboxed execution.

## Proposed Capability

- Type of upgrade: verification convention
- Proposed capability: When adding Python-based HyperAgent verifier scripts, set `PYTHONPYCACHEPREFIX` to a temp directory for compile checks and use `PYTHONDONTWRITEBYTECODE=1` for dry-run execution unless bytecode output is intentionally under test.
- Expected impact: Prevents environment-specific verifier failures and keeps local checks writable inside temporary or repo-owned paths.
- Transferability: Useful for future SDK demos, Python adapters, and eval scripts across Codex workspaces.

## Implementation Plan

- Highest-priority plan step: Add this convention to the next Python-based verifier or contributor guidance update after human review.
- Implementation steps: Document the environment variable pattern; update future verifier templates; optionally add a shell helper if Python examples become common.
- Files or instructions likely to change: `docs/quickstart.md`, `CONTRIBUTING.md`, future `examples/*/verify.sh`, or future verifier templates.
- Verification for the first step: Run the affected verifier in a sandbox where the default Python cache path is not writable and confirm it still passes.

## Safety

- Safety risk: Low; the change narrows write locations for verifier-generated bytecode.
- Permission or authority changes: None.
- Human approval required before activation: yes

## Evaluation

- Eval or acceptance test: A Python verifier using `python3 -m py_compile` passes with `PYTHONPYCACHEPREFIX` set to a temporary directory and leaves no bytecode outside the intended temp path.
- Rollback plan: Remove the convention from docs/templates and let each verifier manage bytecode behavior locally.
- Open questions: Should HyperAgent eventually provide a shared verifier helper for Python examples?
